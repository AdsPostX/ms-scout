## Goal
Close the read→act loop on MONITOR_ALARM cards. Two new button actions — Acknowledge and
Snooze — replace the alert card's buttons in-place via `chat_update`. A re-fire context
block shows snooze history when an alert fires again after being snoozed.

This is the core interaction of Phase 12. Everything in PRs 12-01 and 12-02 was plumbing
to make this PR correct.

## What "in-place update" means
When a user clicks Acknowledge or Snooze, Scout:
1. Reads `alert_registry.get_post_state(alert_name)` to get the message_ts + channel
2. Calls `web.chat_update(channel=channel, ts=message_ts, ...)` with new blocks
3. The original alert card updates in-place — no new thread message for the action itself
4. The button section is replaced with a status chip showing who acted and when

## Re-fire context
When `demand_feed_main` fires an alert that was previously snoozed (snooze_until is set
and has passed), the MONITOR_ALARM card header includes a context block:
"⏸ Snoozed by <@U123> at 2:15pm · re-firing now"

## Snooze modal vs direct snooze
Snooze uses `views_open` — a simple modal with a duration selector (1h, 4h, 24h, 48h).
The trigger_id comes from the block_actions payload. Duration selection is synchronous —
no ClickHouse query — so the modal opens and commits within the 3s trigger_id window.

  + snooze modal builder + result handler
- `scout_ui_kit.py` — `_refire_context_block()` pure function + `_alert_status_chip_blocks()`
